# 开发与验收

本文件维护验证选择规则和根检查入口；两端命令用法分别见 [Web README](../web-demo/README.md) 和 [App README](../app/README.md)，实际命令以仓库脚本和配置为准。当前开放任务见 [CURRENT_STATUS](CURRENT_STATUS.md)，旧阶段计划见 [归档](archive/2026-09-08-before-workflow-cleanup/docs/DEVELOPMENT_PLAN.md)。

根目录可运行 `node tools/check-project.mjs` 检查入口、链接、仓库边界、共享合同和样本完整性；单独数据审计使用 `node tools/audit-datasets.mjs`。这些检查不报告算法准确率。

## 每次改动

1. 确认本次模块、平台及已授权范围，读取该模块权威规范；保留无关工作树修改。
2. 先完成可检查的实现；修正实际失败，不为低影响文案改动机械新增镜像测试。
3. 按下表执行适用检查。相关测试通过后，只有新修改、失败或未解决风险才需要重复或扩大测试；同一轮避免重复构建同一产物。
4. 更新变更规则所属文档；重要交付记录实际范围、命令、结果、环境和未测边界，CURRENT_STATUS 引用该记录。相关入口只检查链接，不复制状态。

## 验证范围

| 改动 | 至少核对的实际边界 |
| --- | --- |
| 文档与声明精简 | UTF-8、相对链接、当前规则不矛盾；若改显示组件，再做对应静态/页面检查 |
| 表单与页面流程 | 类型/静态检查、对应交互、窄屏溢出、取消与错误反馈；存在保存时验证真实写入边界 |
| 计算公式与数值格式 | 零/非法输入、单位换算、上下限、未取整计算与显示精度隔离、两端参考样例 |
| 记录与趋势 | 范围/单值/空插值、日期排序、跨空点连线、五条横滑、列表十条分批、编辑不覆盖原始算法输出 |
| 任务与计划 | 固定日期与旧任务语义分开、发生日例外、跨缸隔离、编辑保留历史、预览/取消无写入、限定范围覆盖 |
| 补液周期（目前仅网页） | 最后一天/逾期、原残液当量和新档位、容量/负药量拒绝、取消不覆盖、旧历史保留、刷新与两药隔离 |
| 数据库/备份 | schema 升级、旧版本兼容、事务回滚、有效性/关联校验、权威恢复、照片/设备通知 ID 剥离 |
| 图像算法 | 三项独立拒绝、质量问题、模板缺失/重复档、ROI 修正与旋转、原始值保留；样本审计与精度评估分别记录 |
| 平台能力或发布包 | 对应构建、模拟器/设备实际流程及日志；通知/相机/后台结论需要真实平台证据 |
| 性能与卡顿 | 按用户反馈定位宿主、模拟器或 App，比较相同场景的修改前后结果，记录下述测量口径 |
| 依赖与构建工具升级 | 保留升级前锁文件和审计结果，核对实际运行产物中的依赖及官方修复版本；同一兼容组合完成构建与对应流程回归，记录未修复项及触发路径 |

App 与 Web 的合同测试直接读取根 [contracts/maintenance-dosing.json](../contracts/maintenance-dosing.json)。合同变化后运行两端相关测试；文件约定见 [技术设计](TECHNICAL_DESIGN.md)。合同测试证明实现一致，不能证明真实投加效果。

先运行覆盖影响范围的检查；迁移、恢复、共享状态或依赖变化无法由定向检查充分覆盖时，再扩大回归。需要验证新产物时再构建；网页完整检查已包含一次构建、SSR 和浏览器流程，纯计算可先跑免构建单元测试。同一工作区的 Flutter/Gradle 构建与代码生成顺序执行。

`dependencies` / `devDependencies` 是包管理分类，不能直接当作部署边界；例如 RSC 运行代码可能由构建工具带入 Worker。报告区分生产包审计、完整依赖树和已确认的实际触发路径，不为降低审计数字盲目跨主版本或迁移到预发布框架。

## 性能测量口径

Windows 任务管理器中的模拟器进程 CPU，与 Android 内 App 进程 CPU 分开记录，不能互相替代。报告注明测量工具、进程/PID、CPU 百分比口径、采样时段、页面与前后台状态，以及 debug/profile/release 模式；在相同设备与设置下比较前后结果。App 进程占用低不能证明宿主模拟器占用低；debug 结果用于定位，模拟器结果不直接代表发布版真机性能或功耗。

## 固定产品合同

- 新周期任务以固定开始日期计算发生日，完成/跳过只作用于该日；旧任务缺少开始日期时保留原推进方式，编辑后转新规则。不得用旧验收要求把所有任务改为从操作时刻推进。
- 模板取色、范围和插值的工程一致性不等于浓度准确率。当前相机不要求先实现任意色卡 OCR/自动定位才允许用户框选；校准和独立真实样本是精度评价工作，见 [拍照规范](IMAGE_ESTIMATION.md)。
- 数据迁移不为旧范围生成虚构中点/插值，不丢用户原记录。界面精简不删除确认保存、覆盖影响及配制/复测要求。
- 平台实施范围遵循 [用户工作方式](PROJECT_CONTEXT.md#用户已确认的工作方式)，具体功能差异见 [同步清单](coordination/app-sync-backlog.md)。

## 开发、设备与发布分开

本地工程检查通过即可表述该范围通过，不需要把整个 iOS 或正式发布门槛作为普通网页改动的前置条件。反过来，源码、模拟器、照片示例或未执行的 CI 配置均不能写成真机或公开发布通过。正式签名、设备回归和算法发布条件继续由 [RELEASE_CHECKLIST](RELEASE_CHECKLIST.md) 约束。
