# 发布检查清单

仅用于实际发布前验收，不作为普通网页改动的额外审批或完整构建要求。勾选须有本次待发布版本的证据，当前通过范围见 [CURRENT_STATUS](CURRENT_STATUS.md)。

## 产品与账号

- [ ] 确定名称、Android applicationId、iOS Bundle ID、版本号和支持范围。
- [ ] 完成图标、截图、商店文案、支持联系方式和公开隐私政策地址。
- [ ] Android 使用正式 release 签名，iOS 配置开发者账号、证书及发布资料；不得发布 debug 签名包。

## 工程与产物

- [ ] 按各端 README 执行待发布版本的静态、单元和流程检查，记录实际版本及结果；不能把工作流配置存在当成 CI 已执行。
- [ ] Android release APK/AAB 构建成功，记录文件哈希、大小和工具版本，检查原生库 16 KB 内存页兼容性。
- [ ] iOS 在 macOS/Xcode 完成 Debug/Release 构建及签名。
- [ ] 明确集成验证采用的已存在脚本/设备流程。当前没有 `app/integration_test` 目录，不把不存在的目录写进格式检查命令；建立该套件后再加入入口。

## 真实设备

- [ ] Android 至少覆盖一台 API 24–32 与一台 API 33+；iOS 至少一台 iPhone。
- [ ] 安装、保留数据升级、冷启动，基本记录/趋势/任务/计算器流程。
- [ ] 相机授权、拒绝、永久拒绝、返回设置、方向、对焦、反光和临时照片清理。
- [ ] 通知授权/拒绝、精确闹钟降级、前后台点击路由、重启、关机恢复与省电策略。
- [ ] 进程终止后的计时草稿、绝对结束时间、放弃草稿无正式记录。
- [ ] 离线、低存储、备份分享/恢复、时区变化、大字体、深色模式及平台辅助功能。

## 数据与安全边界

- [ ] 覆盖支持的历史 schema/备份版本；至少保留早期版本和最近升级版本的真实副本验收。支持范围以 [技术设计](TECHNICAL_DESIGN.md) 及实际迁移代码为准。
- [ ] 升级不丢旧值、任务与关联；旧范围不伪造插值；原始算法结果不被人工编辑覆盖。
- [ ] 完整备份不含检测照片、兼容旧含照片包；验证损坏文件、无效关联、安全解压、空间不足及失败回滚。
- [ ] 时间点与本地日历日期各按其语义处理；跨时区通知重新核对。
- [ ] 建议只读确认值、用户目标与历史，保留来源与复测/停止条件；理论计算不宣称通用安全剂量。
- [ ] 隐私、拍照和商店描述反映当前已实现的辅助功能，不能把 NO3/PO4 资料存在写成真实精度已验证；不支持的模板/试剂不得被宣传为已支持。

## 算法发布门槛

- [ ] 明确以何种辅助功能状态发布，以及允许的试剂/模板和拍摄条件，采用 [IMAGE_ESTIMATION](IMAGE_ESTIMATION.md) 的当前合同。
- [ ] 若宣传准确率、数值误差或改变实验性状态，先按独立液体批次隔离调参与最终验证集，冻结算法/模板/阈值。
- [ ] 报告最近档、范围、插值各自可用/拒绝、覆盖和错误，包含全部失败和严重跨档案例。
- [ ] 只有独立证据达到事先明确的门槛才作相应精度或适用性声明；现有样本及工程回归不能替代。
