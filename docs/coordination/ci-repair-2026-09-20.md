# GitHub Actions 失败修复 · 2026-09-20

最新源码上传成功后，源码提交 1542203 的 Flutter 与 Web 流程失败；工作区检查通过。本轮修复已提交为 [c7d8e84](https://github.com/zhuojun-han/tank/commit/c7d8e84554f7c404bce6facff99713c5f584cffd)，该提交三个云端流程均已完成且结果为 success。

## 原因与修改

- [原 Flutter 运行](https://github.com/zhuojun-han/tank/actions/runs/35491534590) 停在 Dart 格式检查，只有 native_state_store_test.dart 的一个调用需要重新排版。补跑后续测试还发现两处当前备份导出断言仍为 12；改为引用 LocalBackupService.formatVersion，当前 JSON 备份格式 13、数据库 schema 12 和历史兼容测试保持原定义。
- [原 Web 运行](https://github.com/zhuojun-han/tank/actions/runs/35491534572) 的生产构建和单元测试通过，浏览器回归有三项失败。比色上传测试立即读取旧选区，未等待图片校验和解码；鱼目录测试仍使用多选改版前的数量标签和加入按钮。修正等待及选择器，并保留原断言、增强多选与跨缸持久化覆盖。
- 存储测试揭示真实反馈时序问题：检测记录先更新，再等待计时清理，之后才准备保存提示；持久化完成时可能还没有对应提示。鱼类保存也因等待关闭草稿而出现相同情况。浏览器状态更新移到最后一次等待之后，与保存提示一起提交；任务已明确持久化成功后直接显示成功提示。没有改变原生提交、计时取消和草稿关闭顺序，也没有改存档格式。
- 存储失败测试保留检测用例，并增加鱼档案的配额耗尽用例，验证即时失败提示、原存档逐字不变、无成功误报、重试后逐项恢复和刷新读回。
