## 实施顺序与交付关口

### 1. 最小可行版本：先证明网页与原生能连通

- 沿用现有通道协议，为 iOS 增加 Swift WKWebView + Flutter PlatformView，不重写业务页面，也不替换 Android 宿主。
- 将同一份 mobile 静态产物加入 iOS Bundle，构建前检查产物存在；建立独立 iOS 构建配置/Bundle ID，隔离旧入口。
- 首选 WKURLSchemeHandler 提供受控本地页面和照片资源；不照搬 Android 专用 HTTPS 来源，不启用任意文件访问。仅主文档允许原生桥接，外链交系统浏览器，照片只接受合法 token。[Apple WebKit 接口](https://developer.apple.com/documentation/webkit/wkurlschemehandler)
- 在首个 macOS 原型中核对 JS 模块/CSS/图片加载、资源 URL、Canvas 取色、草稿存储和 UUID；自定义 scheme 的来源/安全上下文不预设可用。原生 UUID 或兼容实现替代不适用的 crypto.randomUUID，按 WebKit 支持处理 structuredClone、Array.at 等运行时 API；不扩大桥接权限来绕过加载问题。
- 只做一条纵向流程：飞行模式打开首页 → 创建海缸 → 添加手动记录 → 退出重开后仍在 → 验证第二海缸隔离。

**过关条件：** 实际 WKWebView 离线运行、原生读写和重启恢复通过。若加载/取色方案不成立，先调整宿主方案，不先展开所有功能。未签名模拟器构建仅证明模拟器运行，不能代替手机安装。

### 2. 复用业务与接入手机能力

- 保持海缸管理、鱼类多选/自定义图片、检测与 KH 查表、NO3/PO4 取色、趋势、任务、理论/稳定配液与残液逻辑共用。
- 补 iOS 系统相机/照片选择入口及取消、拒权结果；处理 HEIC、EXIF 朝向、大图压缩，网页用标准图片继续取色。权限拒绝后保留手动录入。
- 备份通过系统“文件”和分享面板导入/导出，CSV 导出维持原语义。Android → iOS 用完整备份迁移，iOS → Android 也验证一次，保持原始 ID、海缸归属和当前备份兼容；不承诺浏览器存档自动同步。
- 保留导入前备份、完整校验与事务回滚；草稿、检测照片、通知授权不作为正式业务备份内容迁移。校正 iOS 权限文案中旧的“照片留档”描述。

**过关条件：** 一次有效旧备份导入、一次损坏备份拒绝且数据未变，真实相机/相册取消和一条完整拍照记录流程通过。

### 3. 通知与任务日期

- 使用 iOS 系统本地通知；已提交通知不依赖网页或 App 持续运行。[Apple 本地通知机制](https://developer.apple.com/library/archive/documentation/NetworkingInternet/Conceptual/RemoteNotificationsPG/SchedulingandHandlingLocalNotifications.html)
- 完成/延期/停止/重新配液及时撤销旧提醒；稍后提醒只改变提醒截止时间，保留任务排期。通知点击等待数据库与网页就绪，再定位到对应海缸/任务。
- 当前插件文档记录 iOS 待投递通知数量限制为 64；按整个 App 汇总、去重、分配名额，优先即将到期、稍后提醒与计时，不把每个任务各自 30 天直接平铺。预留计时/稍后容量，并在启动、恢复、数据提交后补排。[插件维护者说明](https://pub.dev/packages/flutter_local_notifications)
- 不依赖不确定的后台执行持续补排，不承诺长期不打开仍能无限提醒。有限理论计划不能到期后继续通知；专注模式、通知授权与系统摘要对展示效果单独实测。

**过关条件：** 前台、锁屏、划掉 App 后的已排通知与点击定位；稍后提醒退出重开不丢；完成/续配后旧通知取消。调度测试只覆盖新增容量、优先级、预留名额和有限计划停止等关键边界，不预设测试数量、不重复已有排期覆盖。

### 4. iPhone 布局和生命周期

- 复用网页版外观，处理安全区、底部手势条、窄屏、大字体、键盘、日期/时间选择和弹窗关闭。安全区由宿主或网页统一负责，避免双重留白。
- iOS 用界面返回/关闭操作，不沿用 Android 的退出调用；左右滑动趋势不误触系统/网页导航。
- 切相机/文件选择期间保留表单，后台暂停动画；恢复按真实时间刷新。WKWebView 内容进程终止后可重新加载，并从原生草稿恢复，不生成正式记录或演示数据。
- 首轮以用户 iPhone 系统为验收对象，最低支持版本按锁定依赖和实际 WebKit 能力确定；不为标称旧版本兼容引入大量补丁。

**过关条件：** 用户设备上键盘、输入、弹窗、拍照、前后台和重开草稿各走一次，保留可复现缺陷再定向修复。
