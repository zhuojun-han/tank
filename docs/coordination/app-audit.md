## 已确认问题与差异

### APP-AUDIT-001：新增海缸保存后红屏（阻断界面）

复现步骤：设置 → 添加海缸 → 名称输入 `Audit-20260907` → 收起键盘 → 保存。弹窗关闭后全屏显示 Flutter 断言：`framework.dart: Failed assertion: line 6268 pos 12: '_dependents.isEmpty': is not true`。

证据：`03-add-tank.png`、`04-tank-ready.png`、`05-tanks.png`、`06-tanks.png`。其中 `06-tanks.png` 为明确红屏画面。重启 App 后 `07-tanks-after-restart.xml/png` 显示测试缸已经保存，原缸保留；后续切缸正常。没有重复创建测试缸。

只读定位：`settings_page.dart` 中 `_showTankDialog` 在 `await showDialog` 返回后立即 `name.dispose()` / `notes.dispose()`，有早于弹窗退出动画完成释放控制器的嫌疑；`_showParameterDialog` 也采用类似模式。**尚未取得本轮首个 Flutter 异常栈，不能将此猜测称为已验证根因**。`add-tank-error.log` 是当时导出的系统日志，未检索到对应首个栈，里面其他应用的旧系统错误不能用作本次根因证据。未修复。

### WEB-002：PO4 计划允许低于当前缸用户目标下限

实际步骤与结果：

1. 在检测页设置验收缸 PO4 目标为 `0.05–0.10 mg/L`，保存成功：`14-po4-target-saved.xml/png`。
2. 设置 → PO4 氯化镧理论计划，输入当前 `0.23`，目标保持 `0.03`，200 L、每日降幅0.1。
3. 计算成功，显示2天、总母液4.00 ml，没有因目标低于0.05拦截：`24-po4-below-user-target.xml/png`。
4. 点击加入验收缸每日任务并确认，9/7、9/8真实创建两项：`25-po4-save`、`26-po4-confirm`、`27-po4-task-created`。

网页版当前源代码对用户目标下限有额外约束，App 仅有固定0.03门槛，行为不一致。KH 对当前缸上下限的缺失由总调度源码对照确认；本轮没有再次设置KH范围并创建越界KH任务，因此不声称已设备复现KH这一分支。

### 其他已知不同

- WEB-001「仅计算，不覆盖原计划」在本地网页已实现，App 原确认对话框没有该选项；本轮不提前同步。公开网站与本地网页版本需按总调度网页报告区分。
- App KH计划最低保存温度默认 `0°C`，实际页面证据 `51-kh-plan.xml/png`；网页默认20°C。稳定滴定KH页的默认温度为20°C，不能混为同一表单。
- 两端内置鱼目录均9项；App横向卡片、网页纵向列表，布局不同。末尾粉蓝吊与东非金剪刀已实际横滑查看，见 `56-fish-catalog-end`。
- 网页本地存储/网页内提醒与App SQLite/系统通知、备份和真实设备工作流属于不同实现，不是全功能逐项等价。
