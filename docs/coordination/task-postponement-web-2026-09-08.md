# 网页任务顺延与实际完成日期

日期：2026-09-08。范围：网页版任务、补液联动和对应规范；App、计算公式与素材未改动。通用任务登记 WEB-008，补液部分继续归 WEB-005。

## 实现

- 首页、日历、任务列表使用统一的延迟和完成日期弹窗。延迟默认 1 天、只接受正整数；完成默认今天，可补选过去日期，并修改最新实际完成记录。
- 重复任务只保留一个最近待办。未完成随本地日期顺延，后续按间隔投影；确认后从实际完成日期排下一次。自动顺延不写入虚构完成记录，旧逐日记录和旧默认历史保持兼容。
- PO4/KH 有限加药计划按最早未处理日整体顺延，保持剩余天数、剂量说明和任务顺序。替换计划保留真实完成/跳过记录；停止时记录用户当前看到的日期，隔离其他海缸和药剂。
- 补液可独立延迟，提醒日期与原液寿命分开计算。可补选实际配液日；同缸同药新配液确认后关闭上一周期及其延期提醒，残液按所选配液日预填，可手改。
- 保存成功后才反馈完成；取消、非法日期、陈旧操作和存储失败保留原存档。历史页编辑任务取当前排期，周期目录去除重复卡片。

行为权威见 [产品规格](../MVP_SPEC.md#网页完成驱动排期)、[滴定规范](../MAINTENANCE_DOSING_CALCULATOR.md#网页补液周期)；持久化字段见 [技术设计](../TECHNICAL_DESIGN.md#网页数据)。

- 单元测试 142 项通过，覆盖自动顺延、日期运算、历史修正、有限计划顺序/隔离、存档迁移及补液延迟。
- 最终源码的类型检查、全项目 ESLint、生产构建及 2 项 SSR 通过。
- 7 项相关浏览器流程通过：`storage-browser`、`chemical-preview-browser`、`maintenance-volume`、`maintenance-browser`、`maintenance-cycle-browser`、`maintenance-countdown-browser`、`task-postponement-browser`。新流程含 4 组场景，覆盖不刷新跨午夜、取消/非法输入、完成日期修正/重开、历史页改名、有限计划延迟/停止、同缸同药续配和重复卡片边界。
- 迭代中纠正了旧覆盖测试删除已处理历史的预期、精确标签选择器，以及有限计划测试误用普通重复任务专属字段的断言；最终验证使用真实日期发生项、历史保留和 UI 行为。修改后重新构建，测试断言调整直接复用同一产物。
- 项目文档/素材索引检查通过（71 份文档）；已查看 390 px 延迟弹窗与延期后的日历截图，无横向溢出或重复卡片。截图在忽略目录 `web-demo/tests/artifacts/`，不入仓。用户本地入口 `http://localhost:3000/` 返回 200。

命令入口：`web-demo/` 的 `npm run typecheck`、`npm run lint`、`npm run test:unit`、`npm run build`、`npm run test:ssr`；浏览器使用 `BROWSER_CHANNEL=msedge`，独立生产预览 `BASE_URL=http://127.0.0.1:3100`，通过 `npm run test:e2e -- --grep ...` 选择相关流程。测试使用隔离存储和模拟时钟，未改用户在 3000 端口的存档。

## 边界

网页关闭时不运行后台任务，重新打开/恢复前台后按当前日期重算；网页提醒不代表 App 系统通知。App 同步、真机后台提醒、iOS 和公开网站发布未执行。同步授权及待办统一见 [同步清单](app-sync-backlog.md)。
