# App UI 改版规划

2026-09-09 · 状态：用户已授权实施，已完成 Android 本地交付；实证见下方实施记录。

本文件保留为 Flutter 改版的历史方案；用户随后将新 App 方向确定为 [本地网页＋WebView](../PROJECT_CONTEXT.md#后续-app-方向)，后续不再以本文件推进 Flutter 界面重写。已有测试与交付不等于用户认可其视觉效果。

用户已明确要求修改 App，使其与网页版基本一致，并加入网页鱼缸的气泡效果。App UI 以现有网页版为视觉与结构底稿，页面顺序、两列彩色指标卡、配色、按钮、圆环计时、完整月历和设置底部面板均按网页，再适配手机字号、触控和安全区。首次规划基线为 `cd8eca3`；实施与实际验证见 [本轮记录](app-ui-implementation-2026-09-09.md)。

首版提出的默认周日期条、首页任务前置、入口重新分组等与网页不同的结构方案已撤销。以下方案与验证均以本版为准。

## 改版目标

让用户在 App 中沿用网页版熟悉的页面和操作，保留自然珊瑚礁背景、鱼类立绘、现有四个底部页签和简洁中文。卡片与按钮采用网页的柔和填色、细边框和轻层次；鱼缸所有文字、运行时长、编辑操作和库存摘要均在水景图片外。

本规划覆盖 App 展示层与网页结构的对齐；手机适配不另行重排页面或改组入口。新增产品行为仍遵循 [用户工作方式](../PROJECT_CONTEXT.md#用户已确认的工作方式)。上一轮 NO3/PO4/KH 建议文案只是草案，本轮不实施建议算法。

## 视觉与手机适配

| 项目 | 建议 |
| --- | --- |
| 色彩与层次 | 直接沿用网页背景、文字、指标卡和按钮配色；柔和填色、细边框、轻层次，不另拟一套主色或状态色 |
| 指标与卡片 | 首页保持两列彩色指标卡；按钮形态、主次关系、输入框和状态标签按网页对应组件 |
| 字号与间距 | 在网页层级上适配手机可读字号和触控间距；尊重系统字体缩放，窄屏可换行、增高，不挪动区块或丢失关键数值 |
| 安全区与弹层 | 顶栏、底部导航和设置面板避开系统安全区；长内容可滚动，键盘不遮住输入和提交操作 |
| 鱼缸 | 上方为运行时长与编辑，中间只显示水景及鱼，下方为库存；图内不叠加任何文字 |
| 操作 | 位置、顺序与主次层级遵循网页；图标按钮保留可访问名称，不为手机端额外改组入口 |
| 动效 | 鱼缸使用网页同款少量上升气泡，与鱼共用局部动画循环；离屏、后台与减少动画时暂停。交互反馈简短，不做整页每帧刷新 |

点击区域至少 48×48 逻辑像素，正文/关键控件对比度按至少 4.5:1 验收；大字号以重排解决，不能截断关键数值或缩字硬塞。[Flutter 可访问性指南](https://docs.flutter.dev/ui/accessibility)

## 页面方案

### 首页

从上到下严格遵循网页顺序：

1. 顶栏切缸与设置。
2. 鱼缸：图外上方运行时长与编辑，中间纯水景及鱼，图外下方库存摘要；开缸与鱼只编辑入口分别保留。
3. 日期标题。
4. 两列彩色指标卡。
5. 维护建议。
6. 关注指标管理。
7. 每日平衡。
8. 今日待办。
9. 各参数柱状趋势图。

柱图每屏约五次、默认最新、横滑历史；范围无插值保留空位，不能补零或中点。补液周期平日不计待办。UI 不新增“健康分数”，预览示例不替换真实记录。

### 检测与复核

- 沿用网页指标选择与同一套 NO3/PO4 检测界面，当前缸始终明确，试剂可更改。
- 圆环计时、3/5/10 分钟快捷项、自定义分秒、开始与跳过放在同一计时卡内；暂停/继续等既有状态按网页顺序呈现。卡片下方分别为手动录入和照片检测行卡，不另做不同入口结构。
- 旋转按钮紧挨照片，顺/逆时针各 90°；照片实际旋转，取色框按现有旋转/重选合同处理。正方向仍是文字朝上、两行四列。
- 最近色档、候选范围、插值分别显示可用结果或短原因，取色技术详情折叠。复核统一“单值 / 范围”，可编辑插值、日期和备注，明确保存或不记录。
- KH 无计时，直接输入初始容积与剩余溶液，显示一位小数结果后选择录入；手动录入继续可用。
- 普通返回保留 App 草稿与计时提醒，明确放弃才清理；不得因改导航改变异步保存、跨缸或取消边界。

### 趋势与记录

- 顺序为页面标题、参数切换、图表卡（含当前结果与目标）、记录标题及添加按钮；每条记录独立成卡并带参数 badge，不合并成无区分的长文本。
- 保留每屏约五次、横滑历史、范围紫色端点和绿色插值；跨过无插值记录连到下一有效点。单值不重复标上下端点。
- 记录区继续可折叠，先取十条，下滑再追加十条；列表摘要以日期和数值为主，备注留在详情。示意图仅展示少量样例，不代表取消分页。
- 避免大字体下的标签碰撞；图中必要时减少次要刻度，选中记录和可访问文本必须提供完整数值、单位与日期。复用已有限制挂载量的实现。

### 任务与滴定

- 默认展示网页的完整月历及翻月操作，不替换为周日期条。月历之后为所选日任务，再展示计划与记录筛选列表，分别保留其日期与筛选语义。
- 任务卡和按钮布局按网页：主操作完成整行，下排延迟/停止等宽；保留任务详情、实际完成日期和撤销边界，避免同一发生项重复操作。
- 普通任务突出名称/日期；加药任务突出当日执行量；每日平衡突出剩余体积/天数和补液日，分别显示正确状态。
- 配方页先选择 PO4 或 KH，必要输入放前，结果显示配方与可用天数；参考计算与说明展开，不将残液寿命混成新配方寿命。
- 保留延期默认一天、自定义天数、未完成自动顺延、完成日重排及新配液关闭旧补液提醒。重复计划三选项和残液续配校验不动。

### 设置与海缸管理

- 使用网页样式的底部面板，顺序为：海缸管理 → 关注指标 → 目标 → 稳定滴定 → PO4 理论 → KH 理论 → 海盐 → 提醒。App 已有外观、备份等入口保留在这些项目之后，不另按旧草案重新分组。
- 海缸、参数和鱼类管理入口保持明确；编辑其他缸不切换当前缸。计算器只调整展示，不改公式或自动关联泵控制。
- 通知权限和同步状态放在提醒项内；原主题、隐私、导出、恢复、归档仍可访问。
- 清空、覆盖恢复和删除继续保留必要确认，不恢复用户已移除的声明勾选、下载取色记录及重复长提示。

| 收尾 | 整体设备验收与适用构建 | 窄屏/大字/键盘/长列表、动画滚动和恢复前台通过后才更新安装包 |

验收矩阵：320/360/390/430 逻辑宽度；系统字体 1.0/1.3/2.0；浅/深主题；空缸、长名称、多鱼、范围无插值、拒绝估值、无目标、无待办、长备注、补液到期与延期。比较当前与改版后的关键操作步数，不以隐藏必要步骤制造“更简洁”。这些是待执行标准，未宣称通过。

性能保持当前局部重绘、动画可见性/后台暂停和鱼数量上限；用同设备同场景 profile 样本比较滚动、鱼动画及恢复前台，记录帧耗时/峰值内存，不给未经测量的提升百分比。不引入新框架或图表依赖。验证选择沿用 [开发与验收](../DEVELOPMENT_PLAN.md)，依据 [Flutter 性能建议](https://docs.flutter.dev/perf/best-practices)。

## 独立于 UI 的已知事项

上一轮只读建议审核发现：App 缺 KH 专用建议，网页对 KH 使用通用建议；网页“最近记录”依赖数组顺序，编辑日期后可能与 App 的日期排序不一致。它们应独立修复/验收，不能在 UI 改版中悄悄改变规则或再宣称所有边界完全一致。建议草案里的连续趋势、过期记录和 NO3/PO4 联动尚未授权实现。
