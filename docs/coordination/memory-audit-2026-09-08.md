# 内存风险排查与修复 · 2026-09-08

用户要求检查内存失控风险，并明确授权修复。覆盖网页版和 Flutter App；不清用户数据、不同步 WEB-005–008 新功能。

## 已确认问题

| 路径 | 触发条件与修改 |
| --- | --- |
| 两端照片/立绘 | 原先先完整解码再缩图，小文件也可携带巨幅图片。现先检查文件/尺寸/静态格式，App PNG 另限制实际 IDAT 解压输出，限制工作图、释放临时预览并阻止过期上传覆盖新草稿。资源预算只维护在 [拍照规范](../IMAGE_ESTIMATION.md#图片资源边界)。 |
| App 细长立绘 | 固定缩到宽 512 会把 2×4000 放大成 512×1024000；改为按最长边缩小，结果 1×512。 |
| App ZIP 备份 | 原来信任声明尺寸，实际解压后才拒绝；小型伪造 ZIP 已复现。现先核实目录，再分块解压并在输出越界时中止；保留 CRC、SHA-256、旧照片及 ZIP64 合法包兼容。 |
| Web 长历史图表 | 5000 条记录全部挂载为上万 DOM 节点；现只挂载视口附近，保留全量历史、横滑及跨空插值连线，折线 SVG 绘图区也限制为视口大小。 |
| Web 鱼与任务投影 | 动画先展开全部鱼再截取，计划逐组重复扫描全任务，旧历史迁移反复数组查询；现提前停止展开、单遍分组、Set 查询。2500 个独立计划的分组键构造次数由 6257500 降至 5000。 |
| Web 旧存档与提醒 | 停止同时读入各历史版本；长等待超出原生定时上限时分段等待，无效日期不启动轮询。稍后提醒按时间戳而非字符串比较，避免已到期却反复唤醒/写存档。 |

没有通过删除历史、降低测试断言、清空全局图片缓存或修改色差阈值来控制内存。App 工作图缩图会改变大图的参与取色像素，算法准确性仍需独立真实样本验证。

## 浏览器内存对照

Windows / Edge 152.0.4191.66 / Node 24.19.0，相同 390×844 视口、独立浏览器存储、生产 Worker 预览。旧产物为 `07e1915`，新产物为本轮修改；CDP 强制回收后通过 `Runtime.getHeapUsage` / `Memory.getDOMCounters` 采样。

| 5000 条记录场景 | 修改前 JS 堆 | 修改后 JS 堆 | DOM 节点前 → 后 |
| --- | --- | --- | --- |
| 首页 | 9.50 MiB | 3.84 MiB | 34080 → 474 |
| 趋势页 | 13.65 MiB | 4.34 MiB | 57833 → 447 |

30 轮“趋势→任务→检测→首页”切换后，修改前/后监听数各自保持 198/200，文档数始终 1。修改后第 10/20/30 轮 JS 堆为 4.54/4.62/4.65 MiB：该场景未观察到监听或文档持续堆积，不据此保证所有使用方式均无泄漏。

这些数字是回收后的 JavaScript 堆及节点计数，不是浏览器进程总内存、GPU 内存或手机峰值；源图解码保护使用受控小样本验证，未故意触发真实 OOM。原始数据在本地忽略目录 `artifacts/memory-before.json`、`artifacts/memory-after.json`。
