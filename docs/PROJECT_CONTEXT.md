# 项目背景与稳定决策

本文件维护产品定位、架构和用户长期决策；版本、当前待办、测试结果见 [CURRENT_STATUS](CURRENT_STATUS.md)。页面行为与公式分别引用模块规范，不在此复制交付日志。

## 产品与数据

- 面向海水缸；首版 Android/iOS，无需注册、无账号云同步。App 数据在设备本地，网页数据在浏览器本地，两端格式不能直接互换。
- 默认一个海缸，可新增多个；记录、目标、参数启停、鱼类和任务按海缸隔离。停用指标或归档任务不删除历史。
- 内置 NO3、PO4、KH、Ca、Mg、K，可按缸启用和新增自定义参数。手动录入、历史编辑和目标管理不依赖相机。
- 拍照用于辅助比色，用户可修改结果并选择是否记录。原始算法输出与人工结果分开保存；正式检测记录及新备份不保存检测照片。
- 检测短时计时与跨日维护任务是独立模块；权限拒绝不阻断手动记录或 App 内任务管理。

## 两端职责

| 层面 | 网页 | Flutter App |
| --- | --- | --- |
| 用途 | 用户新功能的实现与可检查预览 | Android/iOS 客户端 |
| 界面与状态 | React、vinext/Vite；具体依赖以 package.json 和锁文件为准 | Flutter、Riverpod、go_router；以 pubspec 和锁文件为准 |
| 持久化 | localStorage | Drift/SQLite 与私有文件 |
| 拍照比较 | 浏览器本地图片取色 | 本地相机/图片输入与 Dart 取色 |
| 提醒 | 网页打开时的站内提示 | 平台本地通知，仍需真实设备验收 |
| 数据迁移 | 浏览器旧状态兼容 | 版本化数据库及完整备份恢复 |

计算、颜色比较和日期规则尽量放在纯业务模块；界面负责输入与反馈。两端通过固定参考样例和行为合同核对一致性，不以网页测试替代 App 相机、通知或数据库验证。App 与 Web 统一在根仓库维护；目录、共享合同和 CI 约定见 [技术设计](TECHNICAL_DESIGN.md)，机器检查配置见 [工作区配置](../project-workspace.json)。

## 用户已确认的工作方式

1. 新增产品功能先在网页实现并给出可检查结果；用户确认网页完成并明确要求该功能同步后，再实施 App。新增差异统一进入 [App 同步清单](coordination/app-sync-backlog.md)。
2. 已授权的 App 缺陷修复、性能优化和工程维护直接按授权范围执行，无需重复确认；不顺带同步尚未授权的新功能。
3. 界面保持简明，只保留帮助操作或决策的提示；确认保存、破坏性覆盖、删除等有实际作用的操作仍保留。
4. 相机照片由用户旋转到文字朝上、两行四列，再框选色卡和测试液；不要求冗余取色声明勾选。照片输出格式与记录精度见 [拍照规范](IMAGE_ESTIMATION.md)。
5. 动画鱼缸沿用用户已选自然珊瑚礁背景，内置立绘按用户授权加入两端目录；自定义鱼种与压缩立绘按缸保存。库存数量完整，动画可限制同时显示数量；常规刷新不得重置鱼位置。当前目录与交付记录见 [鱼类目录](coordination/fish-templates.md)。
6. 任务采用用户最新确认的 [排期与历史合同](MVP_SPEC.md#网页完成驱动排期)，旧固定日期决定不再约束网页新排期；平台差异和授权仍由同步清单管理。

## 证据与边界

维护建议只依据确认值、用户目标和已保存历史，引用 [建议规则](ADVICE_RULES.md)。用户主动打开的理论计算器可给可追溯配方，不把它称为通用安全剂量，也不自动控制泵。拍照真实精度、不同设备相机/后台表现与 iOS 验收不得由单元测试或模拟器推定通过。

原始素材在 `resource/`，样本登记在 `datasets/`；人工文件名标签不等于受控实测真值。历史决定和验证保存在 [归档](archive/2026-09-08-before-workflow-cleanup/INDEX.md) 与 `coordination/`。
